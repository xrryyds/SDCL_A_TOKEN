## 5. 分析

### 5.1 反直觉点

预期:首 token 池里只有少数 token 能救回(类似 §3 自由采样的"Okay/Alright 垄断")。
实际:**池里 376 个 token 几乎全部能救回**,且全局分布近似均匀。

### 5.2 机制推测(待验证)

R1-Distill-Qwen-7B 在 T=0 greedy 下,**首 token 一旦被强制成"任意一个合理英文动词/介词开头"(Convert/By/Apply/...),后续 4096 token 仍能 greedy 推导出对答案**——意味着**首 token 选择对最终对错的影响相比 prompt 内容是次要的**。这与 §3 自由采样首 token 集中在 `Okay/Alright` 是两个截然不同的现象:
- §3 反映 **distillation 后模型的自然偏好**(thinking-pattern 默认入口)
- §5 反映 **模型在强制起点下的鲁棒续写能力**

### 5.3 与 OPD 论文(arXiv 2604.13016)机制的关系

OPD §4.2 的核心机制:**effective OPD 来自 student-teacher 共享的 high-prob top-k overlap token 集中(97-99% prob mass)**。

本数据**不符合这个模式**:
- §5 救回的 376 个对首 token **不是 student 的 high-prob top-k**——student 自然 greedy 答错才进 mistake 池,这 376 个对首 token 大多在 student top-k 之外
- §5 救回的 376 个对首 token **也不是 teacher 的 high-prob top-k**(teacher 自己 greedy 也错才需要救)
- 这是 **a posteriori 验证有效**的首 token 集合(强制塞 + 评分得到),与论文 §4.2 的 a priori overlap top-k 概念**不同**

### 5.4 对训练设计的暗示

#### 5.4.1 "在对的 N 个首 token 上加 prob mass"方案的可行性

| 单题 N 区间 | 题量占比 | 直接套用"均匀混合 onehot"的合理性 |
|---|---|---|
| N ≤ 2 (p≤10) | 10% | 合理,接近 1-2 个单点 onehot |
| 2 < N ≤ 23 (p10-p50) | 40% | 可行,β 系数需调 |
| 23 < N ≤ 67 (p50-p75) | 25% | 边缘,会把 student 首 token 概率压得很平 |
| 67 < N ≤ 143 (p75-p90) | 15% | **危险**,等于把 student 首位概率推向均匀分布 |
| N > 143 (p>90) | 10% | **不能用**,会把 student 教傻 |

→ 至少 25% 的题需要做 **top-K 截断**(例如每题最多保留 N=16 或 N=8 候选),否则 mass 摊太薄。

#### 5.4.2 候选裁剪的选择问题(待定)

如果限制每题 top-K,需要决定**用什么准则**:
- (a) student 当前自然 logprob 最高的 K 个(贴近 OPD overlap 机制)
- (b) teacher 当前自然 logprob 最高的 K 个
- (c) 随机抽 K 个
- (d) 按"对答案文本长度短/质量高"排序保留 K 个

每个选择背后机制不同,**没有现成方案**。

#### 5.4.3 后续 span 的处理

500 题 × avg 48.65 = 24326 条 candidate 完整对答案,**全算 loss 显存爆炸**。
合理选项是 1-sample MC(每 step 每题抽 1 条 span),论文 §2.2 Eq 3 sampled-token OPD 的直接类比。
